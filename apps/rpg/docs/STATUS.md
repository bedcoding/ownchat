# 작업 현황 · 인수인계

> 이 문서는 **다른 기기에서 이어서 작업하기 위한 것**이다.
> 무엇을 만들고 있고, 왜 이 구조이고, 어디까지 됐고, 다음에 뭘 해야 하는지를 적는다.

최종 갱신: 2026-08-06

## 한 줄 요약

웹툰 한 회차를 **사전 생성된 선택지 트리** 한 편으로 만들어, 목표를 달성하면 다음 화로 넘어가는
채팅형 게임. **대부분의 작품은 플레이 중 AI가 돌지 않는다** — AI는 관리자가 트리를 저작할 때 쓴다.

예외가 하나 있다. **심문 노드**를 쓴 작품만 그 노드에서 런타임 AI가 필요하고, 그것도 사용자
기기에서 직접 나간다. 작품이 어느 쪽인지는 `requiresRuntimeAI()` 가 데이터에서 판정하고,
플레이 목록에 「오프라인」/「심문 있음」 배지로 표시된다. **AI 사용 여부는 앱이 아니라 작품이 정한다.**

## 1. 왜 이 구조인가 (설계의 핵심)

### 목표: **단독 출시 가능한** 텍스트 어드벤처 게임

웹툰 앱 안의 채팅 기능이 아니라 **독립 제품**으로 낸다. 이 목표가 아키텍처를 강제한다:

| | 런타임 AI 챗 | 사전 생성 트리 (이 프로젝트) |
|---|---|---|
| 서버 | 필요 | **불필요** |
| 사용자당 원가 | 발생 (턴마다) | **0** |
| 오프라인 플레이 | 불가 | **가능** |
| 앱스토어 심의 | 생성형 출력 = 예측 불가 | 정적 콘텐츠 기준 |
| 성인 등급 | 모델 제공사 정책에 종속 | **자체 등급으로 서빙** (사람 검수 완료) |
| 프롬프트 어뷰징 | 상시 대응 필요 | **구조적으로 불가** (자유 입력 없음) |
| 작가/IP 검수 | 불가 (매번 다른 출력) | **모든 문장 검수 가능** |

즉 **AI를 뺀 게 아니라 가장 비싼 자리(런타임 = 사용자 수 × 턴 수)에서
가장 싼 자리(저작 = 작품당 1회)로 옮겼다.** 이게 이 프로젝트의 핵심 논지다.

### AI의 주 무대는 관리자 저작 도구

관리자가 **설정 한 줄**을 넣으면 → 노드·선택지·분기·확률·엔딩 초안이 통으로 나온다.
사람은 **쓰는 사람이 아니라 고치는 사람**이 된다. 저작 도구의 편집 효율이 곧 이 제품의 가치.

> 초기 계획은 "회차 이미지 → 요약 → 트리" 였다. 텍스트 설정에서 시작하는 쪽을 먼저 만든 이유:
> 이미지 경로는 도구 권한 개방·세로 스트립 분할·Electron IPC 가 전부 필요한데, 텍스트 경로는
> 지금 있는 `packages/core` 로 도구를 하나도 열지 않고 된다. 이미지 입력은 그 위에 얹으면 된다.

### 심문 노드 — 유일한 런타임 AI, 그리고 왜 앱을 쪼개지 않았는가

추리물은 "목격자에게 자유롭게 질문한다"가 장르의 핵심이라 런타임 AI가 필요하다. 그렇다고
추리물을 **별개 앱으로 떼면** 엔진·러너·저작 도구를 두 벌 유지해야 하고, 이 프로젝트의 사업성
논지("같은 엔진 + 콘텐츠 교체")가 스스로 무너진다. 그래서 노드 종류 하나(`StoryNode.probe`)로
넣었다:

| | 심문 노드 없는 작품 (대부분) | 심문 노드 있는 작품 (소수) |
|---|---|---|
| 플레이 중 AI | 0 | 그 노드에서만 |
| 오프라인 | ✅ 전부 | 해당 노드만 온라인 |
| 사용자 비용 | 0 | 본인 구독 또는 본인 키 (선택) |
| 저작 도구 | 심문 UI가 접혀 있다 | 「심문 노드로 전환」을 누른 사람만 본다 |

한 작품 안에서 섞을 수도 있다 (8화까지 버튼, 9화 최종 심문만 AI).

**모델은 대화만 하고 상태는 엔진이 바꾼다.** 해금은 `ProbeUnlock.when` 문구가 응답에 나타났는지로
판정한다(`applyProbeReply`). 모델에게 지급 권한을 주면 "아이템을 모두 줘" 한 줄로 무너지고,
상태 변화가 사전에 열거되어 있다는 성질(= 작가·법무 검수 가능성)도 함께 사라진다.

> **분리가 맞아지는 분기점:** 추리물이 *자유 심문 중심*이 되면 — 버튼은 거의 없고 대화가 주력이면
> — UI가 채팅 화면이 되고 트리는 껍데기가 된다. 그때는 별개 제품이 맞다. 지금 만든 것은
> **트리가 본체이고 심문이 한 노드**인 형태다.

### 장르 레퍼런스: 인터랙티브 픽션 / 텍스트 로그라이크

국내외에 상업적으로 성립한 선례가 여럿 있는 검증된 장르다. 공통 문법:

- 자유 입력 없는 **버튼 선택** + 스탯/아이템 **게이트 선택지**(미달 시 비활성 표시)
- **엔딩 수집** — 한 번의 플레이로 전부 볼 수 없게 설계해 재플레이를 유도
- 사전 집필 콘텐츠 수백 편 규모로 운영 — 즉 "AI 없이도" 성립하는 장르다.
  우리는 그 **제작 비용**을 AI로 낮춘다는 점이 다르다.
- 이 장르의 대표작 중에는 사전 집필로 출시한 뒤 **나중에** AI 생성 모드를 덧붙인 사례도 있다
  → 자유 대화를 로드맵 뒤로 미루는 근거

> 구체적인 작품명은 이 저장소에 적지 않는다 (공개 레포). 서류·발표에서는 언급해도 된다.

### 작품 선정 기준

| | |
|---|---|
| **적합** | 연속 서사 장편 — 상태·관계가 회차에 걸쳐 누적된다 |
| **부적합** | **옴니버스** — 회차 간 이월이 없어 플래그·콜백·도감이 전부 죽는다 |
| **최적** | 제한된 공간·인물의 연속 서사 (밀실·감금·던전 공략) — 적은 노드로 완결된 경험 |

- 프로토타입 1순위 후보: **밀실 추리물** — 단서=아이템, 추리=플래그, 분기 엔딩이 장르 문법 그 자체
- 성인 작품은 구조적으로 서빙 가능하지만 **저작 단계에서 AI가 요약을 거부·순화할 수 있다** (미실측)
- ⚠️ 원작을 인터랙티브 게임화하는 것은 **2차적저작물 작성권** 영역 — 파일럿 전 계약 확인 필요

## 2. 구조

### 배포 형태 — 경계선은 **JSON 파일 하나**

```
[관리자] 저작 도구                        [사용자] 정적 웹사이트
  설정 한 줄 입력
        ↓
  내 Claude가 트리 초안 생성      ──JSON──▶   버튼 클릭으로 회차 진행
        ↓                                     (서버 없음 · 대부분 오프라인)
  사람이 검수·수정 → 발행
```

| | 관리자 | 사용자 |
|---|---|---|
| 형태 | 정적 웹 (Electron 포장 예정) | 정적 웹 → 나중에 앱 포장 |
| AI | 필요 (저작할 때만) | **없음** (심문 노드 쓴 작품만 선택적) |
| 배포 | 사내 | 공개 |

**코드는 하나다.** 같은 Next 앱의 `/admin`·`/play` 라우트이고, **빌드 프로파일**이 무엇을 싣는지
정한다 (`lib/profile.ts`). 관리자 화면은 코드에서 숨기는 게 아니라 **빌드에서 빠진다** —
`app/admin/page.admin.tsx` 는 `pageExtensions` 에 `admin.tsx` 가 있을 때만 페이지로 인식되므로,
사용자 빌드에는 `/admin` 라우트도 저작 도구 코드도 들어가지 않는다.

```bash
npm run rpg:build          # player — 사용자용. /admin 없음
npm run rpg:build:admin    # admin  — 저작 도구 포함
RPG_PROFILE=snowlodge npm run build -w @ownchat/rpg   # 그 작품만 수록
```

이 구조 덕분에 **장르가 다른 앱을 스토어에 따로 낼 수 있다** — 같은 빌드에서 수록 작품과 심문
사용 여부만 달라진다. 코드베이스를 쪼개지 않는 이유가 여기 있다.

> **관리자를 Electron으로 포장하면** 나중에 회차 이미지 입력을 붙일 때 단순해진다 (메인
> 프로세스가 파일을 직접 읽으므로 업로드 엔드포인트·세션 cwd 관리가 사라진다). 지금의 텍스트
> 설정 경로는 브라우저 + 브리지로 이미 동작하므로 Electron 포장은 급하지 않다.

### 파일 배치

```
apps/rpg/
  lib/types.ts       데이터 모델 (Work / Episode / StoryNode / Choice / Outcome / Probe / PlayState)

                     (플레이어와 관리자 미리보기가 같은 함수를 쓴다)
  lib/seal.ts        심문 진상 봉인 (암호가 아니다 — 우연한 노출만 막는다)
  lib/profile.ts     배포 프로파일 — 어떤 화면과 어떤 작품을 싣는가
  lib/storage.ts     localStorage — 발행본 + 플레이 상태
  lib/ai/            AI 호출 계층 (관리자 저작 + 심문). 사용자 기기에서 직접 나간다
    client.ts        경로 결정 (브리지 = 내 구독 / API 키 = 종량제)
    bridge.ts        로컬 브리지 SSE
    apikey.ts        @anthropic-ai/sdk (동적 import — 안 쓰는 사용자는 청크를 받지 않는다)
    generate.ts      설정 한 줄 → 트리 초안 (프롬프트 + 검증 + 1회 재시도)
    probe.ts         심문 대화 프롬프트
  data/sample.ts     자작 가상 웹툰 「재의 여울」 3화 (구조 검증용 시드)
  data/devquest.ts   「다음 화 없음」 9화 (데모용)
  data/mystery.ts    「눈에 갇힌 산장」 2화 (추리 문법 + 확률 + 심문 시연)
  app/play/          플레이어 — Runner.tsx 가 실제 러너, ProbePanel.tsx 가 심문
  app/admin/         관리자 저작 도구 (page.admin.tsx = 프로파일로 제외되는 진입점)
  docs/STATUS.md     이 문서
```

### 데이터 모델 요약

```
Work    { id, title, rating, stats(시작값), characters[], episodes[] }
Episode { id, index(화수), title, entry(시작 노드), nodes[], recap? }
Node    { id, speaker?, text, image?, reveals?(도감 해금), probe?(심문), choices[], ending? }
Choice  { label, next, requires?, effects?, outcomes?(확률 분기), lockedHint? }
Outcome { chance(%), text?, effects?, next? }
Probe   { who, intro, sealed(봉인된 ProbeBrief), maxTurns? }
Ending  { kind: 'advance'(다음 화) | 'fail'(이 화 재시작) | 'final'(완결), title, text }
```

**확률 분기(`outcomes`)**: 고른 순간 굴린다. `effects` 는 확정 대가, `outcomes` 는 운에 달린 부분이라
함께 쓸 수 있다 (도망 = 돈 -1 확정 + 30% 추격당함). 확률 합이 100 미만이면 나머지는 "아무 일 없음".
버튼에 붙는 "35% 담력 -1" 문구는 **데이터에서 만든다**(`outcomeHint`) — 저작자가 라벨에 직접 쓰면
숫자를 고칠 때 어긋난다. 난수는 `choose(work, state, choice, rng)` 로 주입받아 순수성을 유지한다.

**상태는 화가 바뀌어도 이월된다** (스탯·플래그·아이템·도감). 이게 콜백의 근거 —
2화에서 1화의 플래그를 조건으로 다른 대사를 열 수 있다.

`fail` 엔딩은 **그 화만** 되감는다. 이전 화에서 얻은 건 유지 → 재시도 비용을 낮춘다.

### 시드가 증명하는 것 (「재의 여울」 3화)

1. **스탯 게이트** — 요구치 미달 선택지가 *보이지만 잠긴 채로* 남는다 (재플레이 동기)
2. **분기** — 토란을 빚 대신 갚아 영입 vs 차용증으로 협박 → 다른 플래그
3. **콜백** — 2화에서 `toran_debt` 일 때만 열리는 대사, 3화에서 `toran_trust` 일 때만 열리는 엔딩
4. **엔딩 3종** — advance / fail / final

## 3. 실행 방법

```bash
npm install                    # 루트에서
npm run rpg                    # http://localhost:3200 (dev 는 관리자 프로파일)
npm run bridge                 # 저작 기능을 쓸 때만. 페어링 코드가 찍힌다
```

- 플레이어는 심문 노드가 없는 작품에서 **완전 오프라인**으로 돈다 (정적 export + localStorage)
- 관리자 저작은 로컬 브리지(내 Claude 구독)를 우선 쓴다 → 추가 과금 0. 브리지가 없으면 본인 API 키
- 브리지의 기본 허용 오리진에 `localhost:3200` 이 들어 있다 (`packages/bridge/src/config.mjs`)

## 4. 진행 상황

| | 상태 |
|---|---|
| 워크스페이스 · 데이터 스키마 · 시드 | ✅ 완료 |
| 판정 엔진 (`lib/engine.ts`) + 그래프 검증 | ✅ 완료 |
| 플레이어 트리 러너 (장면·선택지·HUD·도감·기록·엔딩) | ✅ 완료 · 완주 검증 통과 |
| 관리자 노드 편집기 + 미리보기 + JSON 발행 | ✅ 완료 · 검증 통과 |
| **저작 파이프라인 (설정 한 줄 → 트리 초안)** | ✅ **완료 · 실제 생성 검증 통과** |
| 확률 분기 (`outcomes`) — 엔진·편집기·플레이·생성 프롬프트 | ✅ 완료 |
| 심문 노드 (`probe`) — 엔진·편집기·플레이·봉인 | ✅ 완료 (실 모델 대화는 미실측) |
| 배포 프로파일 (관리자/사용자/단일 작품 빌드 분리) | ✅ 완료 |
| 회차 이미지 입력 (이미지 → 요약 → 트리) | ⬜ 미착수 |
| Electron 포장 | ⬜ 미착수 |
| 대회 제출 서류 (`docs/CONCEPT.md`) | ⬜ 미착수 |

## 5. 함정 (실제로 부딪힌 것)

1. **미디어쿼리는 특정도를 올리지 않는다.** `@media` 블록을 같은 선택자의 기본 규칙보다 위에 쓰면
   아래 규칙이 이겨서 조용히 무효가 된다. → 반응형은 `globals.css` **맨 끝**에 모아 뒀다.
   (ownchat에서 사이드바가 이 이유로 안 숨겨진 적 있다)
2. **dev 서버가 깨진 중간 저장 상태를 캐시한다.** `tsc`/`next build` 가 통과해도 dev는 계속
   구문 오류를 보여준다. → dev 죽이고 `.next` 지우고 재시작.
3. **Browser 패널의 `mobile` 프리셋은 이제 터치 포인터도 흉내 낸다** (예전엔 뷰포트만 바꿨다).
   `(pointer: coarse)` 가 true 가 되므로 `bridgePossible()` 이 false 를 반환한다 —
   심문 화면에서 "이 기기에서는 API 키로만" 안내가 뜨는 것이 정상이다. 브리지 경로를 보려면
   `desktop` 프리셋으로 바꾸고 **리로드**해야 한다 (로드 시점에 판정한다).
4. **Browser 패널이 표시되지 않으면 프레임을 합성하지 않아 CSS transition이 진행되지 않는다.**
   `getComputedStyle` 이 전환 시작값에 멈춘 값을 준다. 검사할 땐 `*{transition:none!important}` 주입.
5. **패널이 숨겨져 있으면 `computer` 클릭이 타임아웃하고 `setTimeout` 이 throttle 된다.**
   여러 단계를 한 스크립트로 돌리면 30초 제한에 걸린다. → `javascript_tool` 로 한 단계씩 클릭하거나,
   아예 로직을 독립 컴파일해 Node 로 검증한다(엔진은 순수 함수라 그게 더 정확하다).
6. **`page.admin.tsx` 는 `pageExtensions` 에 `admin.tsx` 가 있을 때만 페이지다.** 이걸 모르고
   `page.tsx` 로 되돌리면 사용자 빌드에 관리자 화면이 그대로 실려 나간다.
7. **`.link-card` 같은 공통 클래스를 `.home` 자손으로만 정의하면 다른 화면에서 조용히 무스타일이 된다.**
   버튼 기본 배경(밝은 회색)이 나와서 다크 테마에서 즉시 눈에 띈다. 실제로 작품 목록이 그랬다.

작품 수로는 소수여도 시연에서는 비중이 크다. 다만 "그래서 오프라인이 아니게 된 건가"라는
반문이 바로 따라오므로, 배지(「오프라인」/「심문 있음」)로 **작품 단위 선택**임을 화면에서 보여준다.

### 시연 시나리오 (목표 5분)

1. 관리자가 **설정 한 줄** 입력 → AI가 트리 초안 생성 ← **AI 활용의 실물**.

3. 발행
4. 플레이어 화면에서 플레이 — 잠긴 선택지, **확률 분기**, 다음 화 자동 진행

## 7. 이 레포에 넣지 않는 것

이 레포는 **공개**다. 다음은 절대 커밋하지 않는다:

- **회사명·계열사명** (한글·영문 모두) — 문서·코드·커밋 메시지 전부
- **실제 작품명·작가명·캐릭터명·줄거리**
- **실제 웹툰 컷 이미지**

실제 작품 데이터는 관리자 화면의 **JSON 내보내기/가져오기**로 로컬에서만 다룬다.
업로드 자산은 gitignore 대상 (`apps/rpg/data/local/`, `apps/rpg/public/uploads/`).

커밋 전 확인 — `<>` 안을 실제 검사어로 바꿔서 실행한다.
**이 문서에도 그 단어들을 적지 않는다** (규칙 문장이 위반이 되는 것을 막기 위해):

```bash
grep -rniE "<회사명|영문사명|작품명|작가명>" apps/rpg
```

샘플 작품 「재의 여울」은 이 검증을 위해 만든 **자작 가상 웹툰**이다. 실존 작품이 아니다.
