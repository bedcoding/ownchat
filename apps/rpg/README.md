# @ownchat/rpg

웹툰 한 회차를 **선택지 트리 한 편**으로 만드는 게임 + 그 트리를 만드는 관리자 저작 도구.

목표를 달성하면 다음 화로 넘어간다. 1화 → 2화 → 3화가 자동으로 이어진다.

```bash
npm run rpg          # 저장소 루트에서. localhost:3200
npm run bridge       # 저작 기능을 쓸 때만 (터미널 하나 더)
```

## 핵심 전제: AI 는 저작 시점에 돈다

```
관리자 (저작 시점)                    플레이어 (런타임)
설정 한 줄 → 트리 초안           →   발행된 트리를 걷기만 한다
       ↓ 사람이 고치고 발행            (AI 0 · 서버 0 · 오프라인)
```

이 구조에서 나오는 것들:

| | |
|---|---|
| 런타임 AI 비용 | **0** |
| 오프라인 | 플레이 화면이 비행기 모드에서도 돈다 |
| 검수 | 모든 문장이 고정이라 작가·법무 검수가 가능하다 |
| 치팅 | 자유 입력이 없어서 "즉시 완료" 같은 우회가 불가능하다 |
| 등급 | 사전 생성 + 사람 검수라 서빙 정책을 자체 등급으로 정한다 |

### 예외 하나 — 심문 노드

추리물처럼 "목격자에게 직접 물어보는" 것이 장르의 핵심인 작품이 있다. 그래서 **노드 종류 하나**로
자유 질문을 넣어 뒀다. **쓰지 않으면 위 표가 그대로 유지된다.**

| | 심문 노드 없는 작품 | 심문 노드 있는 작품 |
|---|---|---|
| 플레이 중 AI | 없음 | 그 노드에서만 |
| 비용 | 0 | 본인 Claude 구독 또는 본인 API 키 |
| 목록 배지 | 「오프라인」 | 「심문 있음」 |

작품이 어느 쪽인지는 데이터에서 판정한다(`requiresRuntimeAI`). 저작 도구에서도 접혀 있어서,
추리물을 만들지 않는 관리자는 이 필드를 볼 일이 없다.

**모델은 대화만 하고 상태는 엔진이 바꾼다.** 아이템·플래그는 저작자가 미리 적은 문구가 답변에
나타났는지로 판정한다 — 모델에게 지급 권한이 없으므로 "아이템 다 줘" 같은 프롬프트로 게임을
깰 수 없고, 상태 변화가 사전에 열거되어 있다는 성질도 유지된다.

## 화면 둘

- **`/play`** — 플레이어. 장면 컷 + 서술 + 선택지 + 하단 능력치 바
- **`/admin`** — 관리자. AI 초안 생성, 작품·회차·노드 편집, 미리보기, JSON 내보내기/가져오기, 발행

요구치가 모자란 선택지는 **숨기지 않고 잠긴 채로 보여준다**. "저 길이 있다는 건 알지만 지금은
못 간다"가 재플레이 동기가 된다.

확률이 걸린 선택지는 버튼 아래에 실제 확률이 붙는다 — 문구를 손으로 쓰지 않고 데이터에서
만들기 때문에 숫자를 고쳐도 어긋나지 않는다.

```
때린다
30% 체력 -1
```

## 빌드 프로파일

같은 코드에서 서로 다른 물건이 나온다. 관리자 화면은 코드에서 숨기는 게 아니라 **빌드에서 빠진다**.

```bash
npm run rpg:build          # 사용자용 — /admin 라우트도 저작 도구 코드도 없다
npm run rpg:build:admin    # 관리자용 — 저작 도구 포함 (Electron 포장 대상)
RPG_PROFILE=snowlodge npm run build -w @ownchat/rpg   # 그 작품만 수록
```

### Vercel + PostgreSQL 프로파일

같은 `apps/rpg`를 두 형태로 빌드한다.

| 명령 | 결과 |
|---|---|
| `npm run rpg:build:admin` | Electron에 넣을 정적 관리자/미리보기 (`out/`) |
| `npm run rpg:build:hosted` | Vercel용 Next.js 서버 + 공개 플레이어 |

Vercel 프로젝트의 Root Directory는 `apps/rpg`로 둔다. `vercel.json`이 호스팅 빌드 명령을
고정하므로 기본 정적 빌드가 실수로 배포되지 않는다.

로컬에서는 `.env.local.example`을 `apps/rpg/.env.local`로 복사하고 실제 값은 그 파일에만
넣는다. `DATABASE_URL`, `OPENAI_API_KEY`, `ADMIN_SYNC_SECRET`에는 절대 `NEXT_PUBLIC_` 접두사를
붙이지 않는다.

같은 PostgreSQL 데이터베이스를 다른 프로젝트와 공유하므로 `DATABASE_SCHEMA=ownchat`을
사용한다. 모든 RPG 테이블과 마이그레이션 기록은 `public`이 아니라 `ownchat` 스키마 안에
생성된다.

현재 가비아 PostgreSQL 엔드포인트는 TLS 연결 검사에 실패했으므로 데모에서는
`DATABASE_SSL=disable`을 사용한다. 외부 인터넷을 통해 DB 비밀번호와 데이터가 암호화되지
않고 전달되는 한계가 있어, 장기 운영이나 실고객 서비스 전에는 TLS 지원 DB로 이전한다.

```bash
npm run rpg:db:migrate    # DB 최초 1회 및 스키마 변경 후 실행
npm run rpg:hosted        # localhost:3200 호스팅 프로파일
```

- `GET /api/health`: DB/OpenAI 환경 설정 상태 확인. 비밀값은 반환하지 않는다.
- `GET /api/works`: PostgreSQL의 발행 작품을 읽는다.
- 사용자 작품 로딩 폴백: PostgreSQL -> 브라우저 마지막 정상 스냅샷 -> 번들 작품.

현재 DB API는 공개 읽기만 준비되어 있다. 관리자 발행 동기화는 `ADMIN_SYNC_SECRET` 인증을
붙인 쓰기 API가 추가되기 전까지 계속 로컬 저장/JSON 내보내기를 사용한다.

마지막 형태 덕분에 **장르가 다른 앱을 스토어에 따로 낼 수 있다** — 코드베이스를 쪼개지 않고
수록 작품과 심문 사용 여부만 달라진다.

## 플랫폼 이름

시나리오 텍스트에는 `{PLATFORM}` 토큰만 커밋되어 있다. 실제 이름은 gitignore 되는 `.env.local`
에서 주입하고, 없으면 가상 이름으로 떨어진다.

```bash
cp .env.local.example .env.local
```

## 구조

```
app/play/     트리 러너 (플레이어 + 관리자 미리보기가 공유) · ProbePanel 이 심문
app/admin/    저작 도구 (page.admin.tsx = 프로파일로 제외되는 진입점)
lib/types.ts  데이터 모델 (전부 JSON 직렬화 가능)
lib/engine.ts 판정·확률 굴림·심문 해금·검증 (순수 함수)
lib/seal.ts   심문 진상 봉인
lib/ai/       AI 호출 계층 — 사용자 기기에서 직접 나간다
lib/profile.ts 배포 프로파일
data/         번들 샘플 작품
```

저장은 localStorage. 기기 간 이동은 관리자 화면의 JSON 내보내기/가져오기로 한다.

## 알아둘 것

- **dev 서버가 깨진 중간 저장 상태를 캐시한다.** `tsc` 와 `next build` 가 통과하는데 브라우저만
  빈 화면이면 `.next` 를 지우고 다시 띄운다
- **`page.admin.tsx` 를 `page.tsx` 로 되돌리면 안 된다** — 사용자 빌드에 관리자 화면이 실려 나간다
- 심문 진상 봉인은 **암호가 아니다.** 정적 배포에서는 작품 데이터가 사용자 기기로 내려가므로
  작정하면 뜯을 수 있다. 우연한 노출만 막는 수준이고, 그게 서버를 두지 않기로 한 대가다
- 실제 작품 이미지·미공개 회차 정보는 커밋하지 않는다 (`data/local/`, `public/uploads/` 는 gitignore)
